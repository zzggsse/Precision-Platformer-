# 手感调参

所有手感数值都在 **`src/pixelperil/Config.java`**，一个文件管完。
改完跑 `scripts\selftest.ps1`，它会打印实测结果，并断言关卡设计规则没有被破坏。

---

## 一、当前实测值

这些数字是 `selftest.ps1` 实际跑出来的，不是估算：

| 项目 | 实测值 | 说明 |
|---|---|---|
| 满跳高度（按住跳跃键） | **53.20 px = 3.33 格** | 解析解是 56.00 px（3.50 格），离散积分的误差约 5% |
| 轻点高度（只按 1 帧） | **16.72 px = 1.04 格** | 由 `JUMP_CUT_VELOCITY` 决定 |
| 平跳水平距离 | **89.60 px = 5.60 格** | 跑满速后起跳、落回同一高度 |
| 升高 3 格时的水平距离 | **56.00 px = 3.50 格** | 跳上高 3 格的平台时能跨多远 |
| 尖刺致死阈值 | `tileX + inset - PLAYER_W + FORGIVENESS` | 精确到 1px |

> "格"= 16px（`Config.TILE`）。

---

## 二、这些数字就是关卡设计规则

| 想做的事 | 上限 | 建议画法 |
|---|---|---|
| 台阶高差 | **≤ 3 格** | 满跳 3.33 格，4 格上不去。画 3 格最稳 |
| 需要小跳微调的地方 | **1 格** | 轻点能上 1 格（1.04 格） |
| 平地缝隙宽度 | **≤ 5 格** | 平跳 5.60 格。画 4~5 格，留余量 |
| 一边升高一边横移 | 升 3 格时 **≤ 3 格** | 升得越高能跨的越少，画 2~3 格比较稳 |

**注意**：水平距离是按 `body.x` 量的（同一起点基准）。玩家本身宽 8px，
所以贴着平台边缘起跳实际还能再多一点点余量。

**关键约束**：`MAX_FALL_SPEED` 必须 **小于 `TILE`(16)**。这是防穿墙的硬要求，
因为碰撞只检查"新进入的那一列/那一行"。当前是 540，即 9 px/帧，安全。
改大之前先想清楚。

## 三、参数表

### 时间

| 参数 | 默认 | 说明 |
|---|---|---|
| `STEP_SECONDS` | `1/60` | 固定步长。**改这个会同时改变所有物理手感**，一般不要动 |
| `MAX_STEPS_PER_FRAME` | 5 | 单帧最多补算几步，防止卡顿后雪崩 |

### 跳跃与重力

| 参数 | 默认 | 说明 |
|---|---|---|
| `GRAVITY` | 1008 | 重力（px/s²）。与 `JUMP_VELOCITY` 共同决定高度与滞空 |
| `JUMP_VELOCITY` | 336 | 起跳初速度（向上为正，因为世界 y 轴向上） |
| `JUMP_CUT_VELOCITY` | 160 | 上升途中松手后把速度砍到这个值，决定"最矮能跳多高" |
| `MAX_FALL_SPEED` | 540 | 终端速度。**必须 < TILE** |
| `JUMP_BUFFER_FRAMES` | 5 | 落地前这几帧内按过跳跃键，落地瞬间自动起跳 |
| `COYOTE_FRAMES` | 0 | 土狼时间。本类型传统是 0（严格），保持 0 以保留精确性 |
| `MAX_JUMPS` | 1 | 改成 2 就是二段跳关卡。物理已经支持（`jumpsUsed` 计数已实现） |

**跳跃缓冲为什么重要**：这类游戏是高速重试的，玩家连按跳跃的频率很高。
没有缓冲的话，"落地前 1 帧按的跳跃被丢掉"会让手感发涩，而且玩家会归咎于游戏而不是自己。

### 水平移动

| 参数 | 默认 | 说明 |
|---|---|---|
| `RUN_SPEED` | 144 | 最大水平速度（2.4 px/帧） |
| `RUN_ACCEL` | 3600 | 加速度。144/3600 = 0.04s ≈ 2.4 帧到满速 |
| `RUN_DECEL` | 3600 | 松手后的减速度 |

想要绝对瞬时（更硬核）就把 `RUN_ACCEL/RUN_DECEL` 调到 10000 以上。

### 碰撞与宽容

| 参数 | 默认 | 说明 |
|---|---|---|
| `PLAYER_W` / `PLAYER_H` | 8 / 12 | 碰撞盒。**必须 < 16**，否则过不去 1 格宽的缝 |
| `CORNER_CORRECTION` | 3 | 顶头时允许的横向修正上限（px）。设 0 关闭，更硬核 |
| `SPIKE_SIDE_INSET` | 4 | 尖刺判定侧向内缩（px） |
| `SPIKE_BASE_INSET` | 2 | 尖刺判定根部内缩（px） |
| `HAZARD_FORGIVENESS` | 1 | 玩家判定尖刺时四边各内缩（px） |

### 死亡与复活

| 参数 | 默认 | 说明 |
|---|---|---|
| `RESPAWN_DELAY_FRAMES` | 0 | 死亡到复活的延迟。**0 = 瞬死瞬复活** |
| `DEATH_FLASH_FRAMES` | 10 | 死亡爆散特效持续帧数。**不阻塞复活** |

### 显示与摄像机

| 参数 | 默认 | 说明 |
|---|---|---|
| `VIRTUAL_W` / `VIRTUAL_H` | 640 / 360 | 虚拟分辨率。整数倍缩放到窗口 |
| `WINDOW_W` / `WINDOW_H` | 1280 / 720 | 初始窗口大小（正好 2 倍） |
| `TILE` | 16 | 瓦片边长 |
| `SPRITE_OFFSET_X/Y` | -4 / -2 | 精灵相对碰撞盒的偏移（由 `PLAYER_W/H` 和 `TILE` 推导） |
| `CAM_LOOK_AHEAD` | 24 | 摄像机超前量（朝面向方向多看一点） |

## 四、调参的推荐流程

1. **先想清楚要改变什么体验**，例如"跳跃太飘" → 加大 `GRAVITY` 或减小 `JUMP_VELOCITY`；
2. 在 `Config.java` 上改；
3. 跑 `scripts\selftest.ps1`；
4. 看实测值是否还符合关卡设计规则（自检会断言"能上 3 格、上不了 4 格"这类性质，
   破坏规则会直接 FAIL）；
5. 开窗口实际试玩，`F1` 打开判定框确认视觉和判定对得上。

**不要凭感觉调完就提交** —— 手感 bug（高度漂移、贴地抖动、擦边误判、
修正失效、非确定性）在窗口里用眼睛几乎发现不了。自检就是为了替代人工复测。

---

## 五、改 `TILE` 的注意事项

改 `TILE` 会牵动一串东西，**不建议在关卡做了一半之后动它**：

- `assets/tiles/tiles.png` 的瓦片尺寸要重做（`tools/GenAssets.java` 里的 `TILE`）；
- 已有 TMX 的 `tilewidth`/`tileheight` 全部作废；
- `Config.SPRITE_OFFSET_X` 是由 `PLAYER_W` 和 `TILE` 推导的，会跟着变；
- `MAX_FALL_SPEED` 必须仍然小于 `TILE`。

---

## 六、离散积分 vs 解析解

满跳高度实测 53.20px，而 `v²/(2g) = 56.00px`。差的这 2.8px 来自**离散积分**
（半隐式欧拉，1/60 步长）：连续解假设速度平滑变化，而每帧是先扣重力再用新速度位移，
所以实际会略低。

自检里对解析解的断言留了 6px 容差。**想知道真实能跳多高，看自检打印的实测值，
不要用公式算。** 这也是为什么那些关卡设计规则必须基于实测。
